## What blocks V-02-1 through V-02-5 uniformly

Each needs a **licensed** desktop application (Fade In 5, Final Draft 13) operated by a person to author
and export the case documents, plus (for V-02-4/V-02-5) the resulting PDFs. None of that exists in this
environment, and no amount of engineering effort here substitutes for it — this is a hard external
dependency, not a scope choice. What *is* built and real, ready for the day that evidence lands:

- `scripts/build-fixtures.ts` + `test/fixtures/*.doc.json`: the two real screenplay documents
  (`Act 2.fadein`, `Ending-updated.fadein`) converted to `DocumentJSON`, checked in `src/layout/golden.test.ts`
  against spike S2's own confirmed page counts (12, 10) — the one fact about them that needed no PDF.
- `scripts/extract-pdf-lines.ts`: builds the exact `{yBucket, xBucket, text, kind}` structure §37.2
  describes from any PDF's text layer, tested against a minimal hand-built PDF (`src/layout/extract-pdf-lines.test.ts`).
- `scripts/golden-update.ts` + `src/layout/golden-cases.ts` + `test/golden/<case>/fadewright.layout.json`:
  five rule cases (continuation cues, scene `CONTINUED`, a keep chain, dual dialogue, the sentence rule)
  with committed snapshots of this pipeline's own output, regenerated deliberately and reviewed on
  every intentional change — the harness `golden.test.ts`'s eventual PDF-comparison rows would plug
  into once real exports exist, per spec 02 §37.2's own `it.skipIf(!existsSync(referencePdf))` design.
- Not built: `bun run golden:report` (an HTML diff viewer overlaying a rendered page on a reference PDF)
  — there is no reference PDF or renderer output to diff yet, so this would be genuinely dead code
  against nothing; building it is deferred to when the licensed-software step above actually happens.
