# @sudobility/writing_core

> **Git policy.** Commit on `main` while executing a plan task. Push only when
> the user explicitly asks in that turn.

Headless, platform-free writing engine for the Fadewright family: document
model (Yjs), templates, commands, SmartType, per-session undo, and spec 02's
layout/pagination engine (M2: paragraph layout, pagination, dual dialogue,
continueds, revision/lock display, the source↔layout mapping and the
incremental `LayoutEngine`, §33 performance guards). Knows nothing about
accounts, servers or UI.

## Tech Stack

- TypeScript strict, ESM only, built with `tsc -p tsconfig.esm.json`
- Vitest; Bun for installs and scripts
- Published publicly to npm via unified-cicd on push to main

## Structure

- `src/units.ts` — EMU conversions (914 400/in). Lengths are integers everywhere.
- `src/ids/` — prefixed ULIDs; `IdSource` is injected (`createSeededIdSource` in tests).
- `src/hash/` — canonical JSON, SHA-256 (`@noble/hashes`), v1 content hashes (spec 11 §4.2) with `vectors.json`.
- `src/schema/` — Zod schemas; types are `z.infer`. Vocabularies in `vocab.ts` are the single declaration.
- `src/template/` — style resolution, template validation, Enter/Tab flow.
- `src/templates/` — shared seeds, role table, generated Fade In templates (`builtin/generated`), authored templates, locale variants, catalogue.
- `src/model/` — Yjs document creation, JSON conversion, template apply/export, portable positions, validation (`validate/`).
- `src/migrations/` — `DOC_SCHEMA_VERSION` and idempotent steps.
- `src/read-model/` — `openDocument`: order index, element views, scenes, dialogue blocks, outline tree, entities, suggestions, hashes.
- `src/commands/` — registry (`registerCommand`/`getCommand`/`listCommands` operate on one shared default instance; `createCommandRegistry()`, Task 34, gives an isolated one — used by tests, e.g. two files registering the same test command id under `bun test`'s one-process-per-run), origins, wire positions, atomic batches, write policy, text/mark/element/entity/SmartType commands, `page-setup.ts` (`title.setField`, `template.setHeaderFooter`, `template.setSceneNumbering`, `template.setContinueds`, `scene.setOmitted`) and `dual.ts` (`dual.make`/`dual.clear` pair with the PREVIOUS dialogue block or clear by element id; Task 34's `dual.create`/`dual.swapSides`/`dual.dissolve` pair with the NEXT one, forward, or act directly on a group id) and `locking.ts` (`scene.lockNumbers` = Lock/Relock, `scene.unlockNumbers`, `page.lock` = lock every unlocked page so a second run locks A pages, `page.unlock`). `element-ops.ts`'s `positionAfter` (Task 34) is a WeakMap-cached binary search over a sorted position index, not the old O(n) scan; anything that reassigns an *existing* element's `pos` directly (not via `createElement`) must call the file's `invalidatePositionCache` afterward, since a same-size in-place reassignment (`dual.swapSides`) is invisible to the cache's own size check.
- `src/layout/` — `layoutDocument`; after pagination `decorate.ts` adds headers/footers and scene numbers (`DocPage.decorations`) and `title-page.ts` lays out `DocLayout.titlePages` (unnumbered, kept apart from the body `pages`). `continueds.ts` owns `(MORE)`, the synthesized `NAME (CONT'D)` cue and scene CONTINUED text/geometry; `dual.ts` owns dual geometry (§15.2 derivation when the template stores none) and splitting. `locks.ts` resolves `production.pageLocks` to block anchors (a page that began mid-block snaps to the block start), forces a break at each and labels overflow pages from `childSeq` (`DocPage.label/numberLabel/lockId/overflow`); two anchors on one block make a deleted page and `combineDeletedRanges` renders `2-3`. Generated lines come back in `DocPage.lines` with `kind` ≠ `text` (never editable) and, in a dual block, `dualSide`; a dual side's `x`/`width` already carry its column.
- `src/layout/eighths.ts` — scene length and running time (spec 02 §27, Task 33): `sceneEighths(layout, model)` (largest-remainder eighths per page, each scene with text extent gets >= 1, decoration lines excluded, omitted scenes 0; `formatEighths` unreduced), `runningTime(layout, model, template, settings)` (`pages` and `words`; `SceneView.estimatedSeconds` overrides), `formatRunningTime` (m:ss). Adapted to the thin cut: takes `DocLayout` plus the read model (a `DocLine` has an element id, not a scene). `adjust.ts` is `autoAdjustLines(model, template, range, opts)`, a planner that returns `lineAdjust` values (nothing writes them: no `lineAdjust` command exists yet); `LayoutDocumentOptions.lineAdjustOverrides` is its what-if seam.
- `src/layout/output.ts` — `buildElementIndex(layout, model?)` (Task 29, reduced): element -> pages/lines (`linesOf`, `elementsOnPage`, `spanOf`) and per-scene page extent with a label (`sceneExtentOf`, `sceneExtents`), body pages and `text` lines only; plus `docVersionOf(model)` (SHA-256 of the doc's Yjs state vector) and `drawNumbers(line, decorations)` (a line's left/right scene-number `PositionedText`, if any — scene numbering is off by default, `template.setSceneNumbering` turns it on). `GlyphRun.clusterSource` is populated by `measure.ts`/`paragraph.ts`, not this module. Task 34 is fully done (the per-instance registry, `positionAfter` in O(log n), and `dual.create`/`swapSides`/`dissolve`). Tasks 29-32 are all done (`mapping.ts`/`engine.ts`/golden corpus, below). Task 35 is deferred.
- `src/layout/mapping.ts` — Task 30, adapted to the thin cut like Task 29: `pageOf`, `positionToCaret`, `pointToPosition`, `selectionRects`, `positionAbove`/`positionBelow` as free functions over `DocLayout` + `output.ts`'s `DocElementIndex` (not the plan's fuller `LayoutResult`); `engine.ts` forwards to these rather than re-implementing them. Cluster geometry is bidi-aware (an RTL run's clusters walk right to left within the run). Simplifications, stated in the file's own header: hidden-position resolution ("nearest visible") needs the model's element order, which a `DocLayout` doesn't carry, so an unlaid-out element's position returns `null` rather than a guess; a generated line ((MORE), a synthesized cue, CONTINUED) resolves to the nearest real text line by vertical distance, not spec 02's exact head/tail rule.
- `src/layout/paragraph-cache.ts` + `paragraph.ts`'s `ParagraphCache` (Task 31, §31.2): a real, bounded (default 60 MB) LRU-with-pinning cache keyed by `layoutParagraph`'s own `cacheKey` (element content + geometry + decoration + view mode, already reserved via `keyPrefix`) plus `effectiveStyleHash` (two elements sharing a style id with different `ov` overrides no longer collide) and `dt.sourceLength` (generated display text — an omitted scene's `OMITTED` — no longer masks a real source-range change): both closed real, previously-latent collision bugs `incremental.test.ts`'s property test caught. `layoutDocument`'s `paragraphCache` option shares one across calls; a cache hit skips measuring entirely.
- `src/layout/paginate.ts`'s chunked resumption (Task 31, §31.4): `paginate(..., resume?: PaginateResumePoint, { stopAfter? })` stops only right after a page closes cleanly (`page === null`) and reports where to resume: `blockIndex` plus the pending `(CONT'D)` cue, scene continuation count and `panels`-mode `PAGE n (CONT'D)` heading a stop there would otherwise drop — all three are carried, not just the first two (a real, initially-missed gap: `lastHeadingElementId` was added after the other two shipped). `layoutDocument`'s `visiblePageHint`/`budgetMs` (injectable `clock`, platform-free) use this to return `complete: false` plus a `resume` for a long document.
- **`openPage`'s `!prev` check used to mean two different things.** "No previous page in THIS call's own `pages` array" is only "nothing to do" when there is truly no earlier page anywhere (the document's real start); when resuming, it instead means the earlier page lives in a prior, separate `paginate()` call that already returned it. A real bug this session: the ORIGINAL resumability work gated ALL top-decoration handling (pending cue, scene top, `PAGE n (CONT'D)`) behind `!prev` alone, so a resumed call's own first page silently got NONE of them even though `resume` correctly carried the state to reconstruct them — caught by `paginate.test.ts`'s own direct resume tests, not by the higher-level engine/property tests (which never happened to chunk exactly at one of these boundaries). Fixed: the gate is `!prev && !isResuming`. The one piece that still can't be written directly on a resume — a scene-BOTTOM decoration belongs on the PREVIOUS chunk's last page, which this call has no reference to — comes back as `retroactiveSceneBottom` on the result; a caller doing real cross-call stitching must push it onto that retained page's own `decor` itself.
- `src/layout/engine.ts` — `createLayoutEngine(opts)` (Task 31, §8.2): `load`/`applyChanges`/`layout`/`getResult` plus all six of Task 30's mapping functions forwarded. `applyChanges` marks the engine dirty for any spec 01 §10.3 `ModelChange` kind that can affect layout (everything except `tags`/`notes`/`beats`/`shots`/`smartType`/`bin`/`bookmarks`/`macros`/`folders`/`writers`, none of which the thin cut's `GlyphRun.annotations` renders). `layout()`'s `LayoutDelta` (`DocLayoutDelta` here — `DocPage[]`, not `PageLayout[]`) is a genuine, verified diff against the previous result, not an assumption — read the file's own header for exactly which parts of §31.3's "convergence" this does and does not implement, and why (page-locks/labelling/revision-display all currently assume the whole page sequence; retrofitting that is a separate, larger undertaking). `getResult` always runs to `complete: true`.
- Golden corpus (Task 32): `scripts/build-fixtures.ts` converts the two real `~/projects/writing/*.fadein` documents to `test/fixtures/*.doc.json` (`FADEWRIGHT_FIXTURES_DIR` overrides the path); `src/layout/golden.test.ts` checks their page counts against spike S2's own confirmed numbers (12, 10) and its own pinned per-page breakdown. `src/layout/golden-cases.ts` + `scripts/golden-update.ts` (`bun run golden:update`) + `test/golden/<case>/fadewright.layout.json` are five real rule-case regression snapshots (`more-contd-split`, `scene-continued`, `keep-heading-chain`, `dual-dialogue-basic`, `break-on-sentences`), checked by `src/layout/golden-cases.test.ts`. `scripts/extract-pdf-lines.ts` (`pdfjs-dist`) is built and tested against a hand-built PDF but has never run against a real Fade In/Final Draft export — none exists here (licensed desktop software); `docs/verification/V-02.md` records exactly what is and isn't blocked by that.
- `src/smarttype/` — name normalization and harvesting.
- `src/undo/` — per-session undo.

## Patterns

- Every write is a command run through `executeBatch`/`executeCommand`, one `doc.transact` per invocation, carrying a `TransactionOrigin`.
- A command's `run` makes every refusal check before its first write. Every invocation — a single command or a multi-command batch — is rehearsed on a throwaway replica first, so a refusal after a partial write never reaches the live document. `fastPath: true` on a `CommandSpec` opts a *single* command out of that rehearsal (never a batch), trading the safety net for one fewer document clone; it is allowlisted to the keyboard hot path — `text.insert`, `text.insertSoftReturn`, `text.deleteBackward`, `text.deleteForward`, `element.split`, `element.setStyle`, `element.cycleStyle` (`src/commands/builtin.test.ts` pins the list) — because each provably refuses, via `isEnabled` or as the first thing `run` does, before any write. Rehearsal clones the whole document, so it costs O(document size): `src/commands/cost.bench.test.ts` guards the budget at 3000 elements.
- `readOnly` defaults to `isNewerThanCode(doc)` (invariant I20); a caller must pass `false` explicitly to override it.
- Element order is `pos` (fractional, base-62) then id. Never use `Y.Array` for anything people reorder.
- Views from the read model are frozen and replaced, never mutated.

## Gotchas

- **Rebalancing must be deterministic.** `pos` is last-writer-wins per element, so two replicas rebalancing with different keys could interleave into a new order; `rebalancePositions` uses no jitter.
- **FIXED at the real trigger, still a sharp edge on the raw primitive.** `rebalancePositions` generates a brand-new key space from scratch, unrelated to the old one, so an insert computed against the OLD neighbor keys has no way to land correctly once those keys are replaced (`commands/convergence.test.ts` still demonstrates this for the raw function called directly). The actual automatic trigger — I19's auto-repair (`model/validate/structural.ts`), which runs by default on every document open — no longer uses it: it calls `rebalanceDegenerateRuns` instead, which touches only the actually over-long, contiguous runs of positions, bracketed by their real, untouched neighbors, so a concurrent insert anchored anywhere else is provably unaffected (`convergence.test.ts`'s own "FIX VERIFIED" test exercises I19's real repair path directly). Residual, narrower risk: an insert whose anchor is itself one of the degenerate elements, concurrent with the repair that compacts them — `positions.ts`'s own doc comment on `rebalanceDegenerateRuns` explains why closing that too would need a persisted "logical predecessor" no element record carries today. Anything that still wants the old, fully-destructive flatten (`rebalancePositions` directly) owns that risk itself.
- **Relative positions do not survive a new `Y.Doc`.** `DocumentJSON` stores them as `o:<offset>`; `materializeDocument` rebuilds them.
- **Undo grouping is ours, not Yjs's.** `Y.UndoManager` runs with an infinite capture timeout and the wrapper calls `stopCapturing()` from an injected clock; tracked origins are a per-session subclass so another session's typing is never undone.
- **Harvest sets counts, it does not increment them** — the harvester is debounced after edits and must be idempotent.
- **A `revDel` embed occupies one Y.Text index.** Offsets in `TextJSON.embeds[].at` are Y.Text indices; `plain` excludes embeds.
- **Changing any hash rule bumps `HASH_VERSION`**; never regenerate `vectors.json` for the same version.
- **Built-in templates are generated.** Edit `osf.ts`, `shared.ts` or the authored modules and regenerate; never hand-edit `builtin/generated` — `generated/checksums.json` is vendored and the golden test verifies it with or without the research sources.
- **`executeBatch` gives each command after a mutating one a FRESH throwaway model** (`openDocument(doc, deps, { repair: false })`, disposed right after the command), so batch ≡ sequential (`src/commands/batch-equivalence.test.ts` pins it, seeded random sequences included). Moves, scene moves, range edits, duplicates and merges all resolve through `ctx.model`; before this, inside one batch they saw pre-batch order and diverged or refused. A new command may keep reading `ctx.model` before its own first write.
- **`ctx.model` is stale inside a command.** A command runs inside `doc.transact`, and the read model's order index, element views and caches are only refreshed by its observers when the transaction ENDS. Read `ctx.model` before your first write; after writing, read the Y.Doc directly (see `repairDualRuns` in `commands/element-ops.ts`).
- **`textVersion`/`attrsVersion` are per-id high-water marks**, never reset on delete: an id can come back (undo, a rejected tracked delete, a re-import) and a reused id with reset counters would collide with the previous element's cache entry.
- **The command registry is a process-wide singleton.** Registering the same id twice from two test files throws, so the whole suite in ONE process (`bun test`) fails where the configured runner (`vitest run`, one process per file) passes. Reset or scope the registry before relying on a single-process run.
- **A `fastPath` command skips rehearsal, so it must refuse before its first write.** The allowlist (`text.insert`, `text.insertSoftReturn`, `text.deleteBackward`, `text.deleteForward`, `element.split`, `element.setStyle`, `element.cycleStyle`) is pinned by a guard test, and each is on the keystroke path where whole-document rehearsal costs ~30 ms at 3000 elements. Resolve everything that can throw or refuse — `resolveStyle` included — before touching the document.
- **Speaker names strip only known extensions.** `entityNameKey` folds `(V.O.)`, `(O.S.)`, `(CONT'D)` and the template's own extensions list into the base name, but leaves any other parenthetical alone: `MAYA (YOUNG)` is a different character from `MAYA`.
- **`resolveStyle` is memoized on the template object's identity** (a WeakMap), which is the `(templateRevision, styleId)` key spec 01 §3.4.2 asks for because the read model rebuilds its frozen template object on every template mutation. The cached resolution is frozen; mutate a copy.

- **`paginate` decides continueds in `openPage`, once per fresh page**, from the scene of the last placed line and the next row; `y` already includes the top decorations. A dual block is the last block of its run and one pseudo-row (as tall as its smallest legal head) in the chain; `placeDual` does the real placement. The scene-bottom reserve is skipped for a chain that ends its scene.
- **Sentence rule makes tests hard to write.** With `breakOnSentences` a dialogue only splits after a line that ENDS a sentence; test speeches need one short sentence per line or nothing splits.
- **Layout never uses `Math.round`.** Every rounding decision is `round.ts`'s own named function (`roundHalfEven`, `snapToHundredthInch`, …) — spec 02 states which rule applies where, and a bare `Math.round` is the wrong one somewhere on that list often enough that it is worth grepping for before trusting a new layout calculation.
- **Every monospaced Courier family lays out at exactly 10 cpi** (`roundHalfEven(sizeEmu × 3 ÷ 5)`, 91 440 EMU at 12 pt) through `layoutAdvance` (`measure.ts`), overriding the face's own advance — a controller ruling (V-02-7, `docs/verification/V-02.md`), not a per-font accident. Nothing on the measurement path calls `face.advance()` directly; if you find a call site that does, it is bypassing the ruling.
- **`Intl` is banned** (`__guards/platform-free.test.ts`, no exemption exists for it): CLDR-derived data (locale word lists, plural rules, date/number formats) arrives only through the injected `LocaleDataPort` (`template/locale-data.ts`), never a host `Intl` call.
- **Renderers draw, they never lay out.** Nothing in this package assumes a DOM, Skia, Direct2D or PDF target — `DocLine`/`GlyphRun` are host-agnostic instructions; a host renderer reads them, it does not feed back into layout decisions.
- **A shaper-less engine flags `approximateShaping`** (`measureItem`'s own diagnostic) for any tier-2 script measured by summation instead of real shaping. That output must never be persisted, exported or used to place a locked anchor — it is a display-only approximation until a real shaper is available.
- **The §31.3 page fingerprint and `docVersionOf`/`DocLayout.docVersion` are NOT spec 11 content hashes** and must never live in `src/hash` (which owns the versioned, `HASH_VERSION`-pinned `vectors.json` hash family) — they are unversioned, layout-internal convergence/cache-invalidation signals with a completely different job.
- **Metrics ship even when font binaries do not.** `FontRegistry`/`FontFaceMetrics` are pure data (advance tables, generated from real font files at build time, `fonts:generate`); the `Shaper` interface's own `prepareFace(faceId)` resolves a face's bytes before shaping with it, and `createHarfBuzzShaper`'s `HarfBuzzDeps.faceBytes` is the injected seam a host supplies them through — this package never bundles or reads a font file itself.
